Legal basis and data minimisation

  • No breach, no authority to query — the system cannot turn into productivity surveillance.
  • The default query returns a verdict, not coordinates: “is this worker inside the zone?”
  • Coordinates only in a probable collapse case, once, coarsened to three decimals.
  • The SIM cards are employer-issued; queries run under the operator's consent framework.
  • The ledger is itself a per-worker presence record — bounded and counted. Coordinates enter it only after an escalation, once, coarsened to 3 decimals (coordinates stored: —).

Each button builds a site on the server and replays its sweeps. Nothing is pre-recorded: these are the agent's real decisions against the same code the tests run. Add ?pace=5000 to the URL to slow the replay down for narration.

Hot day — the full cycle

Silent watch → the threshold is crossed → a budgeted sweep → a worker falls silent → medic, guaranteed bandwidth, one coordinate → the breach ends and the authority to query lapses.

Collapse, or a dead battery?

Six devices read as unreachable. One is a probable collapse; two a network event; one a battery; one had left. And one the network was simply out of date about — a fresh-fix probe proved it alive.

No breach → zero queries

Two sweeps below the legal threshold. Zero API calls. Purpose limitation is enforced in code, not promised in a policy document.

Planner guard — the model is overruled

The same breach swept twice. A valid re-ordering is accepted; then the model tries to add a worker who is not in the plan and the whole proposal is refused. Both outcomes reach the ledger.

Nokia API down

The circuit breaker opens. Nobody is marked safe, the ledger writes UNKNOWN, and the workers stay in the queue. In a safety system optimism cannot be the default.

Three jurisdictions

Same minute, same temperature. Qatar prohibits, Saudi Arabia permits, the UAE prohibits — a configuration entry, not a rewrite.
